# GLDRUBF v1.0 — история, historical replay и Forward PAPER

Существующий робот SMA20/50: прямой архив **GetCandles**, исследовательское
воспроизведение и отдельный Forward PAPER. Максимум один виртуальный контракт
−1/0/+1. **LIVE, брокерские заявки и Sandbox-торговля не реализованы.**

Сигнал: SMA20 пересекает SMA50 вверх → LONG, вниз → SHORT; отсутствие кросса —
удержание. Для кросса нужна 51 завершённая дневная свеча. Стратегия и основной
транзакционный движок сохранены. Исполнение — только по наблюдаемой котировке
строго после знания сигнала, разворот как CLOSE + OPEN с расходами обеих сторон.

## Windows

1. Установить Python 3.11+, скачать ветку gldrubf-v1-paper-api целиком.
2. Запустить `setup_windows.cmd`. Внешних Python-зависимостей нет; тестам токен не нужен.
3. Запустить `download_candles_windows.cmd`: даты, day/1min, предыдущий снимок
   для сравнения либо пустой ввод. Read-only токен вводится скрыто только в
   локальной консоли либо используется T_INVEST_TOKEN текущего процесса.
   Токен не нужно отправлять в Codex, сохранять в файле или передавать в аргументах.

**Day-история запрашивается без прошлого TradingSchedules.** Конкретная выгрузка
на Windows с настоящим API ещё требует проверки. Конец диапазона exclusive и
не позднее текущего времени UTC.

Новая папка data/fetch_... содержит raw/0000.json и другие исходные успешные
ответы, manifest.json с запросами/хешами, instrument.json с текущими метаданными,
candles.json/CSV с нормализацией и validation.json с проверками. Незаполненный
evidence_template.json предназначен для временных подтверждений/допущений.

Папки не перезаписываются. Изменившаяся/исчезнувшая завершённая свеча блокирует
использование нового снимка, сохраняя оба источника. Первое получение без
предыдущего снимка не обнаруживает старые ревизии. Сравнение действует в пересечении
диапазонов; его границы и полнота указаны в отчёте.

Отсутствие свечи не доказывает выходной или отсутствие торгов. Свечи не
достраиваются. isComplete проверяется, но не превращается в выдуманное время
исторической доступности. UTC provider_day не объявляется автоматически
торговой датой GLDRUBF.

## Historical replay

Запуск: `historical_replay_windows.cmd`. Нужны снимок, отдельный JSON с явными
временными допущениями/подтверждениями, независимые наблюдения цены CSV time,price
и явно заданные расходы/историческая денежная спецификация.

В шаблоне нужно заполнить торговые даты, completed_at и available_at каждой
завершённой свечи; указать источник, kind=historical_assumption либо verified,
периоды допустимого моделируемого исполнения, UID/хеш и источник котировок.
Незаполненный шаблон блокируется. [Схема и ограничения](docs/HISTORY_PAPER_V1_RU.md).

При допущениях результат — исследовательский сценарий, не доказанная историческая
исполнимость. Нельзя автоматически копировать closes в цены исполнения.
Сигнал доступен в available_at; котировка с тем же timestamp его не исполняет.
Будущие данные отклоняются.

Старый `replay_windows.cmd` / команда replay сохранены для daily.csv и
подтверждённого calendar.json. Они не строят календарь из новых raw.
Команда signals — legacy-расчёт по day,close, а не допуск к PAPER.

## Forward PAPER

Запуск: `run_paper_windows.cmd`. Обязательны исходный снимок и **проверенный**
файл evidence: kind=verified, источники подтверждения торговых дат, времени
завершения и покрытия истории. Одного isComplete или выдуманного слова verified
недостаточно: программа проверяет согласованность, подлинность источника требует аудита.

Каждый цикл получает новый снимок GetCandles и сравнивает его с предыдущим.
TradingSchedules вызывается только для текущей UTC-даты. Проверяются UID,
стоимость пункта/шаг, завершённость и покрытие истории, текущие расписание и статус,
свежесть котировки. И время цены, и текущее время должны входить в проверенные окна.

История прогревает SMA без сделок задним числом: сигнал становится известным
после получения данных. Новая завершённая свеча без подтверждения её торговой
даты/времени блокирует работу. Устаревшее покрытие, ревизия или исчезновение ранее
принятой свечи также останавливают цикл; позиция в SQLite сохраняется.

**Без проверенной evidence Forward PAPER запускать нельзя.** Автономное
определение торговой даты/завершения GLDRUBF по одному GetCandles не заявляется.
Для регулярной работы нужно подтверждать новые дни. Процесс с реальным API
на Windows ещё не принят.

## Базы, расходы и API

Разным режимам нужны отдельные базы. SQLite закрепляет режим и контекст;
historical-replay, calendar-replay и forward-paper нельзя незаметно смешать.
Старые базы не переписываются и не мигрируют автоматически. Повторный запуск
с теми же входными данными не дублирует виртуальные сделки.
Для одного виртуального счёта используется та же база и один runner; независимые
базы не нужно воспринимать как единый счёт.

Журналы: fills.csv, funding.csv, bars.csv, quotes.csv, summary.json;
historical-replay добавляет research.json с допущениями и хешами.
SQLite — источник восстановления; CSV — экспорт.

Расходы — явные исследовательские параметры: комиссия RUB за сторону контракта,
неблагоприятное проскальзывание в шагах, фиксированный funding либо дневной CSV.
Это не подтверждённый тариф брокера. Сегодняшняя стоимость пункта не приписывается
прошлой истории. ГО, ликвидации, очередь, bid/ask-spread и полный variation margin
не воспроизводятся. Polling LastPrices не гарантирует исполнимую цену.

REST — шлюз официальных gRPC-контрактов: invest-public-api.tbank.ru/rest, JSON POST,
Bearer. Разрешены только семь read-only методов. PAPER — локальная SQLite-модель;
Sandbox — другой брокерский контур, здесь не используется; LIVE отсутствует.
TLS не отключается, redirects запрещены; ошибки обрабатываются без вывода секретов.

```bat
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -m src.gldrubf_bot.cli --help
.venv\Scripts\python.exe -m src.gldrubf_bot.cli historical-replay --help
```

[Актуальный технический отчёт](docs/HISTORY_PAPER_V1_RU.md).
134 теста фактически прошли на Linux/Python 3.12 и 3.13. Новый Windows/API-запуск
ещё требует подтверждения; тестовые искусственные данные не являются историей GLDRUBF.
Исторические аудиты сохранены: прежнее блокирование raw day-выгрузки снято
прямым GetCandles, но календарь и временные подтверждения этим не создаются.
