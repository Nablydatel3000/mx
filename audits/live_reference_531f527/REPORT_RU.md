## Есть ли старая LIVE SQLite на Jino

**Не установлено: доступа к Jino нет.** Наличие файлов в Git или отказ кода от
старого fingerprint не доказывают существование старой базы на VPS. Утверждать,
что миграция действительно требуется, оснований пока нет.

Одна безопасная команда пользователя для штатного state-каталога:

```bash
sudo stat -L --printf='%n | %F | %s bytes | %y\n' /var/lib/gldrubf-live/live.sqlite3 /var/lib/gldrubf-live/live.highwater.json /var/lib/gldrubf-live/LEDGER_INITIALIZED.json
```

Команда читает только метаданные файлов: не открывает SQLite, не читает токен,
не вызывает API и не меняет службы/состояние. Ошибки отсутствия файлов видны.
Если использовался нестандартный --state, в этой же команде нужен его фактический
путь. Отсутствие штатных файлов не доказывает отсутствие базы в другом каталоге.

Непустой файл по штатному пути — кандидат на проверку формата/версии, а не команда
мигрировать. При наличии базы ничего не удалять, не заменять и не переписывать
fingerprint. При её подтверждённом отсутствии нет старого состояния для миграции.

## Решение

**Сигналы стратегии совпадают.** Критических дефектов в трёх заданных условиях
не обнаружено; исправлений и новых защит не добавляли. Код прошёл указанную
offline-приёмку для подготовки контролируемого LIVE-теста.

Безусловная готовность конкретной установки Jino не подтверждена: открытый факт
в рамках этого задания — наличие/версия фактического LIVE-state. Миграция остаётся
**условным**, а не установленным обязательным блокером. Если старая база есть,
её совместимость требуется разобрать до запуска; её автоматическое принятие
кодом по-прежнему запрещено. Реальные исполнения проверяются только отдельным
контролируемым этапом, который здесь не запускался.

Никаких реальных заявок/отмен, LIVE-активации, deployment и merge не было.
