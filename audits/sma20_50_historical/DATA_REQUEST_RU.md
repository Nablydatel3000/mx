# Какие файлы нужны дальше

Ни токен, ни `/etc/gldrubf`, ни сведения о реальном счёте передавать не нужно.
Работающий VPS не останавливайте и его SQLite не копируйте/не меняйте ради этого
исследования. Достаточно копий уже сохранённых снимков; расчёты будут в отдельной
исследовательской базе, не `/var/lib/gldrubf/paper.sqlite3`.

## Шаг 1 — минимальный пакет для аудита реальной истории

Передайте ZIP **одной целой успешно завершённой папки снимка GetCandles**, а лучше
двух: раннего и позднего с пересечением диапазонов. Выбирайте завершённые папки,
не ту, которую робот записывает прямо сейчас. Внутри должны оставаться:

| Файл | Зачем |
|---|---|
| `manifest.json` | UID, UTC-период, capture time, параметры запросов, SHA256 |
| `validation.json` | Статус, count/complete_count, raw-повторы, gaps, changes/comparison |
| `candles.json` и `candles.csv` | Реальные нормализованные OHLCV, is_complete, provider_day, observed_at |
| `raw/0000.json` и остальные `raw/*.json` из manifest | Исходные ответы свечей, проверка хешей и дублей |
| `instrument.json` | Текущие ticker/UID/секция/tick/граница истории; не историческая спецификация |
| `evidence_template.json`, если есть | Исходный незаполненный шаблон; не заполняйте недоказанными временами |

Такие папки уже лежат на VPS в `/var/log/gldrubf/history/<UTC-время>/`.
Можно скачать завершённую папку через SFTP/WinSCP с правами чтения существующего
администратора. Не меняйте права всего `/var/log/gldrubf` на публичные и не
включайте в ZIP `/etc/gldrubf`, окружение процесса, health credentials или базу.
Если сохранилась прежняя Windows-выгрузка с 608 свечами, приложите её целую папку
тоже. Одного CSV без manifest/raw достаточно лишь для частичного аудита структуры.
UID инструмента — публичный идентификатор, не номер брокерского счёта.

## Если существующего снимка у вас нет

На **отдельном локальном Windows-компьютере**, с копией версии `3097a1b`, можно
использовать имеющийся `download_candles_windows.cmd`:

1. Интервал `day`, начало `2024-11-05` для повторения ранее заявленного периода
   либо подтверждённая более ранняя граница доступности GLDRUBF.
2. Конец exclusive: текущая UTC-дата или раньше, никогда будущая дата. Для
   точного повторения прежнего периода 05.11.2024–04.11.2026 укажите `2026-11-05`.
3. Предыдущий снимок — его реальная папка, если есть; иначе оставьте пустым.
4. Read-only токен вводится скрыто только на вашем компьютере существующим
   запускателем. Не отправляйте его в Codex и не вставляйте в argv/файл.
5. Передайте созданную новую папку `data/fetch_<UTC-время>` целиком. При
   `blocked_revision` сохраните оба снимка и проверки, не стирайте расхождения.

Загрузчик уже вызывает FindInstrument/FutureBy и GetCandles по UID, использует
90-дневные DAY-части без optional limit, сохраняет raw и не вызывает историческое
TradingSchedules. Новая выгрузка не доказывает старую доступность/полноту истории.
Повторная загрузка через некоторое время с `compare` обнаружит будущие ревизии
в общем диапазоне, но не вернёт предыдущие версии, уже потерянные до первого снимка.

## Шаг 2 — блокеры собственно исторического исполнения

Эти файлы нужны до запуска существующего `historical-replay`:

| Нужные сведения | Минимальная форма / происхождение | Можно ли получить существующим API сейчас? |
|---|---|---|
| Исторические дата сессии, завершение и доступность каждой DAY-свечи | `timing_evidence.json` по существующему шаблону: time, candle_sha256, trade_day, completed_at, available_at, kind/source, хеш снимка | GetCandles даёт isComplete сейчас, а не прошлую first-seen availability. Нужен архив наблюдений/официальное подтверждение; нельзя угадать из UTC-даты |
| Независимые цены после сигнала, регулярные marks для просадки | `quotes.csv` time,price + UID/источник/время получения/хеш в evidence; bid/ask при наличии отдельно | GetLastPrices — текущая последняя цена, без исторического from/to. Уже накопленные `quotes.csv` и `forward_checks` дают только фактический короткий Forward-период; год назад их не восстановят |
| Исторические разрешённые окна | execution_windows с проверяемым архивным источником и часовыми поясами | Старый TradingSchedules не использовать. Текущие окна не переносить на прошлые даты |
| Исполнение по M1 | Исходные M1-файлы, UID, источник, параметры/UTC-период и отдельная явная модель исполнения | Existing fetch поддерживает `1min` с суточными частями, но выдаёт свечи OHLCV, не bid/ask или отдельные сделки. Конвертация open/close в quotes — новое допущение, не готовое доказательство исполнения |
| Экономика по датам | Официальные спецификации и изменения: tick, tick amount/RUB-point, размер контракта, ГО long/short, валюта, даты вступления | FutureBy/GetFuturesMargin доступны read-only, но дают текущие данные без historical date; нужны документы/архив MOEX |
| Комиссия | Публичный тарифный план и версии по датам, биржевые сборы и порядок включения в комиссию; без аккаунтных данных | В allowlist клиента нет метода истории персональных тарифов; публичные документы брокера |
| Финансирование | Ставки, расчётные даты/UTC-моменты, правила и стороны начисления; `day,long_cost_rub` только если подтверждено соответствие дневной signed-модели | Нет метода historical funding в allowlist; нужен официальный архив/расчётные документы, не фиксированная тестовая константа |

Поле `quotes_sha256`, quote_uid/quote_source и execution_windows требуется
самим replay. Полные OHLCV нельзя молча заменить массивом closes для входов.
Новые источники/методы потребуют отдельной проверяемой интеграции: менять allowlist
работающего PAPER здесь не предлагается.

Необходимое ограничение: при изменявшихся RUB/пункт, tick, комиссиях или начислениях
существующий движок с константами может не воспроизвести реальную экономику. Сначала
подтверждаем факт/даты изменений, затем отдельно решаем способ исследования,
не переписывая торговые правила предположениями.

Если прошлые времена публикации/архив цен недоступны, варианты честно различаются:
сценарный тест по явно согласованным допущениям или независимый Forward-сбор.
Оба нельзя объявлять доказательством исторической исполнимости и прибыльности.
Первое требуемое действие сейчас — **передать полный DAY-снимок из шага 1**.
