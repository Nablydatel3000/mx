# Конкретные данные для следующего сценария

Текущий выполненный сценарий считает только gross-пункты по DAY-open. Ниже
проверена **возможность по существующему коду/контрактам**, не заявлено успешное
получение авторизованных данных. API и токены в Codex не использовались.

| Данные | Через существующий read-only API? | Что остаётся |
|---|---|---|
| Исторические M1 OHLCV по UID | **Да:** `ReadOnlyClient.candles`, GetCandles, `CANDLE_INTERVAL_1_MIN`; клиент делит запрос на сутки, без optional limit. `download_candles_windows.cmd` поддерживает `1min` | Доступность конкретных старых минут/глубина архива требует реального локального запроса; пустота не доказывает отсутствие торгов |
| UID/текущая спецификация | **Да:** FindInstrument, FutureBy, GetFuturesMargin, уже в allowlist | Текущее значение не доказывает историческое; проверить UID `b347fe28-0d2a-45bf-b3bd-cda8a6ac64e6` |
| Прошлые first-complete/available_at DAY | **Нет в ответе GetCandles** | Архив публикаций/историческая схема агрегации либо явная задержка как сценарное допущение |
| Исторический bid/ask/рыночные fills | **Нет** в имеющейся исторической выгрузке. GetLastPrices не имеет from/to | M1 — OHLCV, не исполнимая цена/спред. Нужен архив котировок/сделок либо явно сценарный slippage |
| Исторические торговые окна | Текущий TradingSchedules не даёт доказательства прошлых сессий | Архив расписания/извещения биржи и точное соответствие DAY-label; текущий календарь не переносить на прошлое |
| Исторические tick, RUB/tick, размер контракта и ГО long/short | GetFuturesMargin/FutureBy возвращают **текущие**, без даты запроса | Документы MOEX и изменения по датам, включая способность держать один контракт на заданном капитале |
| Комиссия брокера/биржи | **Нет** метода истории тарифа в allowlist | Тарифный план, версии документов, включение биржевых сборов, база расчёта и даты; без аккаунтных данных |
| Реальное funding | **Нет** метода исторического funding в allowlist | Расчётные ставки/события/UTC-время и формула GLDRUBF из официального архива; не подменять стоимостью при подтверждении свечи |

Подтверждённая RUB-стоимость пункта нужна для комиссии в RUB и доходности капитала.
Если менялась во времени, нельзя применять одну сегодняшнюю константу к двум годам.
Тарифы/источники и ограничения предыдущего доступа сохранены в
`../sma20_50_historical/sources.json`; в этой работе новые численные значения
не выдумывались. Spread/slippage и funding не объявляются фактически нулевыми.

## Минимальная практическая выгрузка

Сначала запросить девять окон из [m1_requests.csv](results/m1_requests.csv).
Это конкретные **начальные UTC-диапазоны**: от даты сигнала до двух календарных
дней после модельной даты входа, конец exclusive. Два дня — технический запас
запроса для проверки соседних меток/границ, не задержка исполнения, не подбор
параметра и не доказательство полного охвата биржевой сессии.

На отдельном локальном Windows-компьютере, с версией `3097a1b` или неизменным
клиентом этой ветки:

1. Запустить существующий `download_candles_windows.cmd`, выбрать `1min`.
2. Для первого окна ввести начало **2025-02-21**, конец exclusive **2025-02-26**.
   Остальные восемь диапазонов указаны в CSV. Токен — только скрытым локальным
   вводом штатного запускателя. В Codex ничего секретного не присылать.
3. Сохранить каждую новую папку `data/fetch_*`: `minute.csv`, `instrument.json`.
   Записать from/to UTC, время получения, версию кода и SHA256 файлов. Убедиться,
   что UID совпадает с DAY-архивом. Старые файлы не перезаписывать.
4. У существующего M1-export **нет raw/manifest**, как у DAY. Для более строгого
   архива происхождения нужен локальный исследовательский сборщик raw-ответов;
   работающий робот/его allowlist для этого не меняются.

После проверки публикации DAY найти первую допустимую M1 **после** available_at
и согласованной задержки, проверить регулярную фазу и сопоставить open с DAY.
Пока available_at/сессия не доказаны, даже M1-исполнение останется явно сценарным.
Если начальное окно не покрывает нужную сессию, расширить сбор до её подтверждённых
границ, а не считать первый попавшийся open пригодным. Результат не должен
зависеть от выбора удачной минуты. Конверсию M1 в модельные quotes описать и
хешировать; фактическими fills её не называть.

Девяти окон достаточно только для первичной проверки входов/разворотов. Для
**внутриминутно недоказанной, но более частой M1-просадки** нужна история за все
удержания, ориентировочно с **21.02.2025 по 18.11.2026 exclusive** в рамках
доступной истории. Последний mark текущего теста — 17.11.2026; не примешивать
незавершённый текущий день. Для проверки bid/ask и очереди нужны другие данные.

Нужен также исходный журнал прежних **+4220 пунктов**: период, входы/выходы,
сигналы, учёт последней позиции и расходов. Пока его нет, расхождение −73,7
между ним и close-reference текущего архива остаётся неидентифицированным.

Следующий тест сохраняет SMA20/50 и один контракт. Модель времени/исполнения и
расходы согласуются явно, без оптимизации SMA, отключения проверок или вмешательства
в PAPER. Положительный gross-пунктовый результат сам по себе не основание для LIVE.
