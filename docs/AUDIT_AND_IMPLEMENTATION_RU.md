Исходные тесты **фактически запускались до изменений:6, OK**. Их успех не подтверждал перечисленные отсутствующие функции. Повтор исходного набора из Git-архива также сохранён в журнале проверок.

## 2. Что реализовано

### API

`api.py`: официальный REST read-only клиент стандартной библиотеки. Есть allowlist семи методов Instrument/MarketData, нет счетов, OrdersService, стоп-заявок или sandbox-orders. Token только T_INVEST_TOKEN в окружении процесса; нет аргумента token/config-файла, response body/headers/transport exceptions не выводятся. Redirect запрещён, чтобы не пересылать Authorization на новый адрес. Timeout20сек, bounded retry для429/5xx/ошибок соединения,401 не повторяется бесконечно.

UID GLDRUBF ищется по точному ticker+futures; неоднозначность требует явного UID. FutureBy проверяет UID/ticker/RUB/lot1/шаг/биржу. Используются UID, включая текущий GetFuturesMargin.instrumentId. Стоимость API-пункта=current minPriceIncrementAmount/minPriceIncrement; она проверяется перед очередной обработкой. Изменение спецификации не вызывает скрытую переоценку базы.

История chunked (DAY90дней,1MIN1день, limit2400), только EXCHANGE source. Конфликтующие дубли/чужой диапазон/невалидный OHLC/volume отклоняются. Учтена документированная включительность конечной DATE и игнорирование time-of-day у DAY: физическая граница экспорта всё равно исключительная. LatestPrice запрашивается EXCHANGE с UID/status проверкой, нельзя исполняться по будущей/устаревшей цене или при неподтверждённом торговом статусе.

Календарь не строится по Mon–Fri. Основная/вечерняя/премаркет сессии и clearing читаются из API. Финальная граница учитывает аукцион закрытия. Свеча допустима для сигнала только если isComplete и подтверждённый конец дня уже прошёл; текущая незавершённая свеча отложена, историческая незавершённость/пропуск не замалчиваются. Даты — label провайдера; timezone-aware времена приведены к UTC, Windows local time не используется. Неизвестные новые detailed intervals отклоняются, а не интерпретируются по неизвестному строковому названию.

**Проверены актуальные публичные контракты**, а не только старый Tinkoff mirror: [RussianInvestments/investAPI,commit3eaf23a25f598fe483c913184acdbd9132bc68d2](https://github.com/RussianInvestments/investAPI/tree/3eaf23a25f598fe483c913184acdbd9132bc68d2). Прочитаны api_protocols.md, faq_marketdata.md, instruments.proto, marketdata.proto. Это источник интерфейса/REST адреса, **не успешный запрос авторизованного рынка**.

### Сигналы и PAPER

SMA20/50 по закрытию, crossing rules/равенства и0=удержание сохранены. Параметры стратегии/количество контрактов не оптимизируются и не выставляются в CLI. Валидация не превращается в альфа-фильтр.

`engine.py`: no broker access. Отдельные bar/known_at и quote events. Исполнение требует quote.time>signal-known-at; цена сигнальной свечи не используется как fill. При API-наблюдении known_at — после загрузки истории, не предполагаемое прошлое время доступности. После простоя несколько кроссов меняют последний pending, без ретроспективных fills. Виртуальный разворот atomic CLOSE→OPEN, с проверяемым промежуточным position0, максимум±1.

Комиссия фиксированная RUB/сторона, adverse slippage ticks, стоимость пункта и начальный RUB cash зафиксированы в metadata. Чистый результат=gross−commissions+signed funding. Unrealized по последней наблюдаемой цене отдельно; equity=initial+net+unrealized. Финансирование — **явная дневная модель**, fixed assumption либо переменный CSV. Начисляется по позиции перед официальным окончанием торгового дня. Нет ставки для удержанного дня →вся batch-транзакция откатывается. Пересмотр уже применённой ставки обнаруживается. Неторговые funding-даты внутри обрабатываемого диапазона не игнорируются молча: модель их не поддерживает и останавливается.

### Восстановление и Windows

База хранит UID/стоимость/настройки, bars/payload/known_at/target, quotes, fills, funding, текущие позицию/entry/финансы/pending. Повторы идентичны и не дублируют fills. Новая цена по тому же времени/исправленная закрытая свеча/другая конфигурация не принимаются тихо. Восстановление сверяет cash/position с ledger и PRAGMA quick_check. Legacy target-only база не мигрирует в выдуманные fills и остаётся побайтно неизменной при отказе запуска нового engine.

CLI поддерживает signals/fetch/replay/paper. Journals — SQLite и CSV/JSON/операционный log. Export берёт один DB-snapshot; файлы заменяются через временные, DB остаётся источником истины при сбое экспорта. Runner lock не допускает второй CLI процесс с той же базой. SQLite защищает транзакции дополнительно.

Windows `.cmd` и интерактивный модуль позволяют работать без написания Python. Setup создаёт venv, запускает тесты, не запрашивает token. Runtime token вводится скрыто только при отсутствии env и живёт в окружении процесса. Пользователь вводит настройки расходов как данные, не программирует. Четыре launchers описаны в README.

## 4. Неустранённые ограничения

1. Требуется настоящий read-only smoke на Windows: проверить наличие GLDRUBF, конкретный UID/exchange, minPriceIncrement/Amount, дневной label/финальную границу сессии и реальные варианты intervals. При неизвестном поле календаря программа останавливается; прототип не объявляется совместимым с любым будущим изменением API.
2. Дневные свечи могут уточняться после isComplete; revision вызывает отказ, а не скрытое изменение истории. API outage может задержать исполнение; после восстановления нет попытки выдумать пропущенную цену.
3. Polling LastPrices использует первую **наблюдённую** новую цену, не все биржевые тики/стакан. Spread/queue/liquidity/partial broker fills не воспроизводятся. Положительное slippage — явное допущение. Сигнал и позднее исполнение разделены, но это ещё не высокоточный бэктест.
4. Финансирование фикс/CSV — дневная модель, не автоматический источник фактической ставки GLDRUBF и не полная внутридневная формула бессрочного фьючерса. Выходные начисления/несколько settlement-событий не реализованы. Процентные/оборотные реальные комиссии нужно преобразовать в подтверждённые расходы, не считать фиксированный ввод тарифом брокера.
5. Не воспроизводятся ГО, маржинальная ликвидация, брокерский variation margin и историческая динамика стоимости пункта. API-PAPER фиксирует текущую спецификацию и останавливается при её изменении. Исторический replay требует подтверждённых исторических коэффициентов; единый коэффициент не применять ко всему периоду без доказательств.
6. UTC внутри Python хранится с микросекундной точностью; равное время с иной ценой — остановка, а не угадывание порядка. Хранить sqlite на локальном диске, не синхронизировать активную БД через облачную папку. На Windows поведение блокировки/кодировок требует отдельной приёмки.
7. Пока нет CI Windows и длительного непрерывного запуска. Нет deployment, платного хостинга, LIVE, реальных заявок, оптимизации и вывода о математическом ожидании.

## 5. Приёмка пользователем

Сначала setup_windows.cmd →фактический журнал 42 тестов Windows. Затем download_candles_windows.cmd с read-only token →сверить UID/official sessions/дневные candles с терминалом/документацией. Далее новый PAPER DB, явно заданные реальные либо исследовательские расходы →дождаться pending и следующей свежей цены; проверить две стороны разворота/экспорт. Остановить и возобновить с той же БД; не должно быть повторной операции. Не превращать технический replay в заявление о доходности. При несовпадениях сохранить обезличенный log/metadata, token не отправлять.

Draft PR предназначен для ревью реализации и ограничений. Main не объединяется и реальные средства не подключаются.
