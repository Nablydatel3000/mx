# GLDRUBF: архив GetCandles и автономный Forward PAPER SMA20/50

PR: https://github.com/Nablydatel3000/mx/pull/1. Ветка gldrubf-v1-paper-api,
base main. Без merge, deployment, LIVE и брокерских заявок.

Ручное подтверждение каждой исторической свечи блокировало текущий PAPER.
Теперь стандартный запуск сам загружает DAY через GetCandles, принимает только
isComplete=true и рассчитывает прежние пересечения SMA20/50 по наблюдаемым
агрегатам. Время знания фиксируется при принятии данных; исторических исполнений
нет. UTC-label сохраняются независимо от дня недели, MSK используется для
отображения. Торговая дата и полнота архива не объявляются доказанными.

Исполнение требует текущих расписания, торгового статуса и свежей более поздней
котировки. Запрашиваются только сегодня/завтра для ночных окон. SQLite сохраняет
один контракт, расходы, целевую позицию и идемпотентность после перезапуска.
Ревизия/исчезновение завершённых свечей и запоздалые вставки в принятый SMA-префикс
останавливают цикл; временные сетевые сбои повторяются без закрытия позиции.
Новый режим использует отдельную базу и явную стоимость финансирования за новую
подтверждённую свечу, не подменяя её историческим клирингом.

Существующие загрузчик, неизменяемые raw-снимки, защита HTTP, исторические режимы
и сигнальная функция сохранены. Убраны ручная evidence и генерация её шаблонов
из стандартного Forward; historical replay сохраняет явные временные допущения.
Windows: setup_windows.cmd → run_paper_windows.cmd; начальный снимок необязателен.

188 offline-тестов прошли на Linux/Python 3.12 и 3.13, включая непрерывный цикл
с имитацией API, возобновление SQLite, выходные UTC, незавершённые свечи, пропуски,
ревизии, устаревшие цены и сохранение позиции при сбоях. Windows CI уже настроен;
новый реальный запуск Windows/API в этой среде не выполнен. Прибыльность не оценивалась.

При несовпадении текущего календаря Forward теперь сообщает запрошенную секцию,
публичные коды ответа и число точных совпадений. Отдельный Windows-диагностический
запуск сравнивает фильтр FutureBy.exchange и запрос без фильтра; ни смены секции,
ни обхода контроля окон нет. По реальному ответу пользователя подтверждено
расхождение регистра FutureBy и TradingSchedules. [Прежний разбор](CURRENT_SESSIONS_RU.md),
[проверки](CURRENT_SESSIONS_TEST_RESULTS.txt).

Для случая requested_exchange=other/returned_exchanges=[other] добавлена
изолированная локальная команда diagnose_exchange_codes_local_windows.cmd.
Она показывает фактические коды, не применяет публичный allowlist, скрывает
отражённый токен/небезопасные строки и запрещает перенаправление вывода.
Файлов/публичных логов не создаёт. [Инструкция](LOCAL_EXCHANGE_CODES_RU.md).

Сопоставление исправлено минимально: исходный FutureBy.exchange сохраняется в
запросе; выбор требует ровно одного casefold-совпадения. Отсутствие/неоднозначность
блокируют работу. Диагностика различает literal exact_matches и casefold_matches,
не раскрывая неизвестные коды в публичных логах. Парсер days, стратегия,
PAPER/SQLite и торговые проверки сохранены. Для пользовательской пары кодов,
коллизий регистра и интервалов выбранной записи добавлены шесть регрессий.
[Результаты и остаточная Windows-проверка](EXCHANGE_CASEFOLD_RU.md).

Для последующего реального STOP о неподдержанном detailed interval добавлен
изолированный снимок TradingSchedules: diagnose_schedule_snapshot_windows.cmd.
Он сохраняет локально только коды секций, UTC-границы запроса, дни/флаги, типы и
границы detailed intervals и 13 legacy timestamps. Отдельная проверка JSON
отмечает пропуски/аномалии без разрешения исполнения. Есть offline --validate.
Все существовавшие Python-модули этим последним изменением оставлены без изменений;
parse_day, стратегия, PAPER, SQLite и торговые ограничения не корректировались.
Реального снимка пока нет; ошибка интервалов не объявляется исправленной.
[Диагностика, официальная схема и передача файлов](SCHEDULE_SNAPSHOT_RU.md).
