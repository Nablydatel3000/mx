# GLDRUBF: архив GetCandles и автономный Forward PAPER SMA20/50

PR: https://github.com/Nablydatel3000/mx/pull/1. Ветка gldrubf-v1-paper-api,
base main. Без merge, deployment, LIVE и брокерских заявок.

Ручное подтверждение каждой исторической свечи блокировало текущий PAPER.
Теперь стандартный запуск сам загружает DAY через GetCandles, принимает только
isComplete=true и рассчитывает прежние пересечения SMA20/50 по наблюдаемым
агрегатам. Время знания фиксируется при принятии данных; исторических исполнений
нет. UTC-label сохраняются независимо от дня недели, MSK используется для
отображения. Торговая дата и полнота архива не объявляются доказанными.

Исполнение требует текущих расписания, торгового статуса и свежей более поздней
котировки. Запрашиваются только сегодня/завтра для ночных окон. SQLite сохраняет
один контракт, расходы, целевую позицию и идемпотентность после перезапуска.
Ревизия/исчезновение завершённых свечей и запоздалые вставки в принятый SMA-префикс
останавливают цикл; временные сетевые сбои повторяются без закрытия позиции.
Новый режим использует отдельную базу и явную стоимость финансирования за новую
подтверждённую свечу, не подменяя её историческим клирингом.

Существующие загрузчик, неизменяемые raw-снимки, защита HTTP, исторические режимы
и сигнальная функция сохранены. Убраны ручная evidence и генерация её шаблонов
из стандартного Forward; historical replay сохраняет явные временные допущения.
Windows: setup_windows.cmd → run_paper_windows.cmd; начальный снимок необязателен.

157 offline-тестов прошли на Linux/Python 3.12 и 3.13, включая непрерывный цикл
с имитацией API, возобновление SQLite, выходные UTC, незавершённые свечи, пропуски,
ревизии, устаревшие цены и сохранение позиции при сбоях. Windows CI уже настроен;
новый реальный запуск Windows/API в этой среде не выполнен. Прибыльность не оценивалась.
