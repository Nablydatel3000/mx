# GLDRUBF: минимальное исправление регистра идентификаторов календаря

17.11.2026. Ветка gldrubf-v1-paper-api, PR #1. База: 08dcf71078fcb2083e73cf82f86131a6b2cd1235.

## Проверка → результат → ошибка → исправление → решение

**Проверка:** реальный результат пользователя: FutureBy.exchange —
`forts_futures_weekend`, отфильтрованный TradingSchedules возвращает одну запись
`FORTS_FUTURES_WEEKEND`; без фильтра присутствует то же имя. HTTP 200, структура
корректна. Эти наблюдения предоставлены пользователем, не получены запросом из Codex.

**Результат и ошибка:** прежнее побуквенное равенство отвергало одинаковые имена
в разных регистрах. Редактирование обоих значений в other скрывало это различие.

**Исправление:** единая функция exchange_matches сравнивает две строки только
через casefold(). Исходный FutureBy.exchange не меняется в запросе. Оба выбора
календаря, current_sessions и schedules, требуют len(matching)==1. Две записи,
равные после casefold, дают неоднозначность даже при одном побуквенном совпадении.
Нет trim, alias, замены разделителей, объединения записей или подстановки FORTS/MOEX.

Диагностика использует тот же критерий. exact_matches сохраняет побуквенный счёт,
casefold_matches — новый счёт для допуска выбора. Категория успешного сравнения
кодов в публичном контроле теперь calendar_casefold_match. Локальная команда
по-прежнему показывает исходные строки и не пишет файлы; публичная диагностика
сохраняет редактирование неизвестных имён. Подтверждённый код специально не
добавлялся в публичный allowlist.

**Сохранённые проверки:** парсер parse_day не изменён: trading flag, пары границ,
аукционы, клиринг, детальные интервалы и конфликтующие записи дней проверяются
прежним кодом. Неподдерживаемый подробный интервал остаётся причиной остановки.
Пустые days не становятся разрешением торговли. Требования текущего статуса,
реальных окон now/quote, свежести цены и отсутствия будущих данных сохранены;
стратегия, autonomous runner, PAPER-движок и SQLite не изменены.

**Тесты:** шесть новых методов проверяют пользовательскую пару и смешанный регистр
в обе стороны, сохранение исходного параметра запроса в обоих методах, ноль
совпадений без эвристик, коллизию из одного literal и двух casefold-совпадений,
счётчики диагностики, обработку интервалов после выбора. На синтетическом расписании
проверены обычная/вечерняя сессии, исключение клиринга и аукционов, end-exclusive,
отказ неполных границ/неизвестных intervals/конфликта days. Проверяется именно
выбранная запись, соседняя секция не используется.

Полный набор: 180 тестов на Linux/Python 3.12 и 3.13 с ResourceWarning как ошибкой,
compileall и git diff --check. [Журнал](EXCHANGE_CASEFOLD_TEST_RESULTS.txt).

**Решение:** подтверждённый дефект сравнения регистра исправлен и покрыт тестами.
Это не подтверждает успешный Forward PAPER на Windows. Полные реальные days и
intervals пользователем ещё не предоставлены и здесь не проверялись; фикстуры
не объявляются реальным календарём GLDRUBF. Новый авторизованный запрос не выполнялся.

На Windows получить обновлённую ветку, выполнить setup_windows.cmd и повторить
run_paper_windows.cmd с прежней базой/расходами. При другом STOP не сбрасывать
SQLite и не обходить checks; изучить безопасную категорию ошибки. Диагностика
кодов может показывать exact_matches=0 и casefold_matches=1 — это ожидаемо для
подтверждённой пары, а не проверка всех торговых разрешений. Реальные заявки,
LIVE, merge и deployment не выполнялись.
