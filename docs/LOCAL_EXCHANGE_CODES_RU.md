# GLDRUBF: фактические коды календаря только в локальной консоли

17.11.2026, gldrubf-v1-paper-api, PR #1. База: 018decd153c400e8721e5ce5de71df7f36035333.

`other` в публичной диагностике — результат редактирования неизвестного кода,
не строка от API. `exact_matches=0` при двух `other` означает несовпадение исходных
значений, а не равенство. Из этих данных нельзя вывести правильный код календаря.
**Проблема не объявляется решённой: нужен реальный ответ новой диагностики.**

## Запуск Windows

1. Получить обновлённую ветку целиком; при необходимости выполнить setup_windows.cmd.
2. В обычной локальной консоли Windows запустить
   **diagnose_exchange_codes_local_windows.cmd**. Не использовать `>`, pipe,
   Tee-Object, Start-Transcript или запись терминала.
3. Ввести read-only токен скрыто. Токен не передавать в Codex, файлы или аргументы.
4. Прочитать три строки: instrument, current_filtered, current_unfiltered.
   Никаких исторических дат и evidence вводить не нужно.

Прямой запуск из папки репозитория:

```bat
.venv\Scripts\python.exe -m src.gldrubf_bot.diagnose_exchange_codes
```

Команда требует TTY для stdin/stdout. При обычном перенаправлении отказывается
работать до ввода токена и запросов API. Она не может обнаружить внешнюю запись
экрана или transcript интерактивного терминала: такую запись нужно выключить.
При category=console_required_or_diagnostic_failure проверить запуск из обычной
консоли; это безопасная общая ошибка без текста исключения, не доказательство
проблемы API. Закрытие окна не сохраняет результаты в проекте.

## Какие значения передать для анализа

Только следующие поля, сохраняя регистр, символы, порядок и повторения:

- instrument: **instrument_exchange** (источник FutureBy).
- current_filtered: **requested_exchange, returned_exchanges, returned_count,
  exact_matches, http_status, category, from_utc, to_utc**.
- current_unfiltered: те же поля; exchange_filter должен быть omitted.
- При ошибке API: безопасные **grpc_code/api_code**, если присутствуют.

Токен, Authorization, UID, accountId, полный API-ответ и снимок всей консоли
передавать не нужно. `[redacted]` означает подавленную небезопасную строку;
не пытаться прислать её без редактирования. Новая команда не заменяет коды на other.

## Изоляция и ограничения вывода

Используется существующий ReadOnlyClient: FindInstrument(query=GLDRUBF), затем
FutureBy(idType=UID,id=найденный UID). Проверки GLDRUBF/RUB/lot=1 сохранены.
Выводится именно Future.exchange, не realExchange/classCode. Два запроса
TradingSchedules используют тот же конструктор current_schedule_request(), что
PAPER: от текущей UTC-полуночи до +2 дней. Первый передаёт исходный exchange без
изменений; второй полностью опускает поле exchange. Attempts=1, retries нет.

Из ответа проецируется только exchanges[].exchange. Список сохраняет порядок
и дубли; исходные значения сравниваются точно. Вывод допускает не перечисленные
в публичном allowlist идентификаторы до 128 символов из ASCII букв/цифр/`_`/`.`/`-`,
с начальной буквой/цифрой/`_`. Свободный текст, управляющие символы, чрезмерные
строки и значения, содержащие текущий токен, заменяются на `[redacted]`.
Это ограничение вывода, не подстановка в запрос или подбор кода.

Команда не использует logger, не создаёт файлы, не читает счёт, свечи, котировки
или SQLite и не запускает PAPER. При HTTP-ошибке выводятся только безопасные
статус/числовые коды, не exception/message/тело. Второй запрос выполняется даже
после ошибки первого. Код выхода 0 — ровно одно совпадение в каждом ответе,
а не проверка days/торговых окон и не разрешение исполнения.

api.py, стратегия, PAPER-движок, SQLite и механизм исполнения этой поставкой
не изменены. Выбор первой записи, замены FORTS/MOEX, объединения секций и fallback
нет. Публичные логи PAPER сохраняют редактирование unknown → other.

## Что говорит официальный контракт

Повторно проверены четыре источника из
[реестра CURRENT_SESSIONS_SPEC_REFERENCE.json](CURRENT_SESSIONS_SPEC_REFERENCE.json):
официальный investAPI HEAD 3eaf23a25f598fe483c913184acdbd9132bc68d2,
SHA всех четырёх файлов совпали 17.11.2026.

- instruments.proto и OpenAPI: Future.exchange — торговая площадка/секция;
  TradingSchedules.exchange — необязательное имя биржи или расчётного календаря;
  отсутствие фильтра возвращает все доступные площадки. Ответ exchanges содержит
  exchange и days. Это строки, не закрытый enum.
- По смыслу корректно искать запись календаря с тем же именем секции. Но контракт
  не содержит отдельного GLDRUBF/UID → calendar mapping и не гарантирует наличие
  каждой Future.exchange в любом календарном ответе. У TradingSchedules нет
  параметра UID инструмента. Поэтому совпадение проверяется по реальным ответам;
  преобразование разных имён требует подтверждения поставщика, а не догадки.
- markets.md различает FORTS и FORTS_EVENING. Описание общей части расписания
  не доказывает эквивалентность кодов для конкретного GLDRUBF.
- head-instruments.md: расписания доступны от текущего дня, не в прошлом;
  расписание брокерской секции может отличаться от биржи, необходим текущий статус.

Если точное имя отсутствует и в запросе без фильтра, безопасный способ пока не
установлен: нужны ответы и подтверждение Т-Инвестиций о соответствии секции
GLDRUBF календарю. Если без фильтра оно есть, это наблюдение о расхождении ответов,
не автоматическое разрешение сменить рабочий запрос. Контроль окон не отключается.
